# سَكَن | نظام إدارة سكنات الطالبات

تصميم وتطوير سور للبرمجيات — soursoft.om

## خطوات التشغيل

### 1. بناء قاعدة البيانات من الصفر
افتح Supabase ← **SQL Editor** ← الصق محتوى `database/00-sakan-schema.sql` ← **Run**.

تحذير: الملف **يحذف كل الجداول والدوال وكل حسابات المستخدمين** في المشروع، ثم يبني كل شيء من جديد.
لا يحذف صور البطاقات المرفوعة سابقاً؛ لحذفها: **Storage ← id-cards ← احذف الملفات**.

بعد التشغيل يوجد "السكن الرئيسي" بأربع غرف، لتستطيع المشرفات والطالبات اختياره عند التسجيل. عدّله أو احذفه لاحقاً من لوحة الإدارة.

### 2. تفعيل الحسابات فوراً (بدون رسالة تأكيد بالبريد)
Supabase ← **Authentication ← Sign In / Providers ← Email** ← أوقف **Confirm email** ← **Save**.

إن تركته مفعّلاً، يصل لكل مستخدم بريد تأكيد، ولا يستطيع الدخول قبل الضغط على رابطه.

### 3. إنشاء الحسابات
كل دور له صفحة إنشاء حساب وصفحة دخول:

| الدور | إنشاء حساب | تسجيل الدخول |
|---|---|---|
| الطالبة | `signup.html` | `login.html` |
| المشرفة | `supervisor-signup.html` | `supervisor-login.html` |
| الأمن | `security-signup.html` | `security-login.html` |
| الإدارة | `admin-signup.html` | `admin-login.html` |

- الطالبة تختار سكنها عند التسجيل، والإدارة تحدد الغرفة ورقم البصمة لاحقاً من **الحسابات ← تعديل**.
- المشرفة تختار السكن الذي تشرف عليه، وترى طلبات وحضور طالباته فقط.
- كل الحسابات تعمل فوراً بعد التسجيل.

### 4. (اختياري) رمز تسجيل لكل دور
التسجيل مفتوح لكل الأدوار، أي أن أي شخص يعرف رابط `admin-signup.html` يستطيع إنشاء حساب إدارة.
لتقييد ذلك دون تعديل أي كود، ضع رمزاً للدور من SQL Editor:

```sql
update settings set value = 'رمز-سري-للإدارة' where key = 'signup_code_admin';
update settings set value = 'رمز-للمشرفات'   where key = 'signup_code_supervisor';
update settings set value = 'رمز-للأمن'      where key = 'signup_code_security';
```

بعدها لا يُنشأ حساب لهذا الدور إلا بإدخال الرمز في خانة "لديكِ رمز تسجيل؟". لإلغاء الرمز: `set value = null`.

### 5. تجربة الموقع على الكمبيوتر
لا تفتح الصفحات بالضغط المزدوج على ملفات HTML؛ المتصفح يمنع تشغيل الكود عند فتحها كملفات.
فك ضغط المجلد بالكامل، ثم شغّل **start-site.bat** (ويندوز)، فيفتح الموقع على `http://localhost:8080`. اترك النافذة السوداء مفتوحة.

### 6. الرفع على الاستضافة
ارفع كل الملفات كما هي في نفس المجلد. الموقع صفحات ثابتة تتصل بـ Supabase، ولا يحتاج خادماً.
إن غيّرت رابط الموقع، أضفه في Supabase ← **Authentication ← URL Configuration ← Site URL** حتى تعمل روابط تأكيد البريد.

### 7. ربط جهاز البصمة
على كمبيوتر في السكن متصل بنفس شبكة الجهاز:
1. ثبّت Node.js 18 أو أحدث.
2. سجّل حساباً من `security-signup.html` مخصصاً للربط.
3. في مجلد `device-bridge`: انسخ `.env.example` باسم `.env` وعبّئه ببريد الحساب وكلمة مروره وعنوان الجهاز.
4. شغّل `start.bat`.

يسحب البرنامج البصمات كل 30 ثانية. عند تعطله يستطيع الأمن إدخال رقم البصمة يدوياً من لوحته.

## كيف تعمل الخدمات

| الخدمة | المسار |
|---|---|
| الحضور | الطالبة تسجّل من الموقع ← تبصم على الجهاز ← "حاضرة". البصمة بدون تسجيل مسبق لا تُحتسب. |
| تصريح الخروج | الطالبة ترفق صورتي البطاقتين وتُقرأ آلياً ← المشرفة ← الأمن: استلام البطاقة ثم التحقق ← تسجيل الخروج ← تسجيل العودة. |
| الاستضافة | الطالبة ← المشرفة ← الأمن يسجّل دخول الضيفة ومغادرتها. |
| تغيير الغرفة | الطالبة ← موافقة المشرفة تنفّذ النقل مباشرة. |
| النقل بين السكنات | الطالبة ← المشرفة ← الإدارة تعتمد وينفَّذ النقل. |

لا يُقبل طلب نقل إلى غرفة ممتلئة، ويُعاد التحقق من السعة لحظة التنفيذ.
صور البطاقات في تخزين خاص (`id-cards`)، ولا تراها إلا الطالبة نفسها ومشرفة سكنها والأمن (للتصاريح المعتمدة) والإدارة.

## ملفات المشروع
- `database/00-sakan-schema.sql`: بناء قاعدة البيانات كاملة (الجداول، الدوال، الصلاحيات، التخزين).
- `main.js`: الدخول ولوحات المشرفة والأمن والإدارة وتصريح الخروج وقراءة البطاقات.
- `sakan-features.js` و `sakan-shared.js`: إنشاء الحسابات، الحضور، الاستضافة، النقل، الإشعارات، وصفحات الإدارة الإضافية.
- `style.css` و `sakan-features.css`: التنسيق (ومدمج أيضاً داخل كل صفحة).
- `start-site.bat` و `server.ps1`: تشغيل الموقع محلياً على ويندوز.
- `device-bridge/`: برنامج ربط جهاز البصمة.
